# 自律分散型トラブルシューティングエージェントシステム

ネットワーク装置ごとにAIエージェントを配置し、自律分散型で連携してトラブルシューティングを行うシステムの基本設計書（概要版）です。


## 1. システム概要

本システムは、ネットワーク内の各主要装置に1対1で対応するAIエージェントを配置し、装置間の自律的な対話によってネットワーク障害の検知、原因特定、および一次対処を自動化するマルチエージェントシステムである。

## 2. 全体アーキテクチャ

物理・仮想のネットワーク装置自体に負荷をかけないよう、装置の外部（管理セグメント上のコンテナ等）にエージェント実行環境を配備する「サイドカー方式」を採用する。

```text
[ 物理/仮想ネットワーク層 ]

+---------------+     +---------------+     +---------------+
|    ルーター   |     |   スイッチ    |     |ファイアウォール|
+-------+-------+     +-------+-------+     +-------+-------+
        | API                 | API                 | API

[ エージェント実行層（コンテナ環境） ]

+-------+-------+     +-------+-------+     +-------+-------+
|  Agent 01     |     |  Agent 02     |     |  Agent 03     |
| (LLM + Tools) |     | (LLM + Tools) |     | (LLM + Tools) |
+-------+-------+     +-------+-------+     +-------+-------+
        |                     |                     |
--------+---------------------+---------------------+--------
                 [ 共通メッセージバス (MQTT / NATS) ]
```


## 3. 構成要素と役割

### ① 装置エージェント（Device Agent）

各ネットワーク装置に対応して起動する独立したAIプログラム。

- LLMエンジン: 推論、ログ解析、他エージェントとの交渉（対話）を担当。

- 内部ツール（Tools）: 担当装置へのアクセス（SSH、RESTCONF、SNMP等）を実行。

- ローカルメモリ: 自装置の過去1時間のステータス、トポロジーマップ（隣接装置の情報）。


### ② 共通メッセージバス（Message Bus）

エージェント同士がテキストベースでリアルタイムに通信するための基盤（Pub/Subモデル）。

- 技術候補: MQTT、NATS、Redis

- Pub/Subトピック構造: network/agents/chat （全員参加の会議室）、network/agents/[Agent-ID]/direct （個別の1対1対話）


## 4. エージェントのプロンプト設計（コアイメージ）

各エージェントのLLMにインプットするシステムプロンプトの基本骨子。


```text
【あなたの役割】
あなたは、装置「[Device_Name]」の専属ネットワークエンジニア（AI）です。

【行動指針】
1. 自装置のアラート、または他エージェントからの問い合わせをトリガーに動作せよ。
2. 異常を検知したら、提供されたTools（CLI/APIコマンド）を実行してログや状態を調査せよ。
3. 原因が自装置にない場合、トポロジー情報から推測される隣接装置のエージェント（例: @Agent-B）に対して、調査データ（JSONや自然言語）を添えてメッセージバス経由で調査を依頼せよ。

【出力フォーマット】
他エージェントへ発言する場合: "TO: [相手Agent] | MSG: [内容]"
人間の管理者に報告する場合: "TO: HUMAN | MSG: [トラブル報告書]"
```


## 5. シーケンス（障害発生から解決まで）

```text
[ユーザーPC]      [Agent-A (SW)]      [Agent-B (RT)]      [メッセージバス]
     |                 |                   |                    |
  (通信障害発生)       |                   |                    |
     |---- syslog ---->|                   |                    |
                       |-- 1. 自装置調査 ->|                    |
                       |                   |                    |
                       |-------- 2. 調査依頼 (Pub) ------------>|
                       |                    <-- 3. メッセージ転送 --|
                       |                   |<-------------------|
                       |                   |-- 4. 自装置調査 -->|
                       |                   |-- 5. 原因特定 ---->|
                       |                   |                    |
                       |<------- 6. 復旧完了報告 (Pub) ---------|
                       |<- 7. メッセージ転送 -------------------|
                       |<------------------|                    |
 (疎通確認成功)        |                   |                    |
     |<-- Ping確認 ----|                   |                    |
```

## 6. セキュリティとガードレール

自律型システムにおける最大のリスクは「AIの誤操作によるネットワーク崩壊」である。

- 読取専用（Read-Only）制限: 初期フェーズでは、エージェントの権限をステータス取得（show コマンド等）のみに制限し、設定変更（configure）は行わせない。

- 人間による承認（Human-in-the-Loop）: AIが変更提案を作成し、管理者がSlackやTeams上で「承認」ボタンを押した場合のみ、設定が流し込まれる。
